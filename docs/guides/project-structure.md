# TestNauti Project Structure

## Directory Layout

```
⛵️ TestNauti.co/
├── code/                          # Main Next.js application
│   ├── src/                       # Application source code
│   │   ├── app/                   # Next.js app router pages
│   │   ├── components/            # React components
│   │   ├── data/exams/            # Exam JSON files (generated)
│   │   ├── lib/                   # Utility libraries
│   │   └── types/                 # TypeScript type definitions
│   ├── prisma/                    # Database schema & migrations
│   ├── public/                    # Static assets
│   ├── package.json               # App dependencies
│   └── ...config files            # Next.js, TypeScript, Tailwind configs
│
├── scripts/                       # Transformation & utility scripts
│   ├── transform-nautical-exam.ts      # Single exam transformer
│   ├── batch-transform-exams.ts        # Batch exam transformer
│   ├── update-exam-registry.ts         # Auto-update loadExams.ts
│   └── README.md                       # Scripts documentation
│
├── examenes/                      # Source exam JSON files (input)
│   ├── exam-69.json
│   ├── exam-70.json
│   └── ... (60+ exam files)
│
├── EXAM_IMPORT_GUIDE.md          # Quick reference for importing exams
├── PROJECT_STRUCTURE.md          # This file
└── ... (other root-level files)
```

---

## Directory Purposes

### `/code/` - Application Code Only
**Purpose:** Contains the Next.js application and all code required to run the app.

**What belongs here:**
- Application source code (`src/`)
- Database schema (`prisma/`)
- Static assets (`public/`)
- Configuration files (Next.js, TypeScript, Tailwind, etc.)
- Package dependencies (`package.json`, `node_modules/`)
- Build output (`.next/`)

**What does NOT belong here:**
- ❌ Data transformation scripts
- ❌ One-time utility scripts
- ❌ Source/raw data files
- ❌ Build tools unrelated to the app

---

### `/scripts/` - Utility Scripts
**Purpose:** Standalone scripts for data transformation, batch processing, and maintenance tasks.

**What belongs here:**
- ✓ Exam transformation scripts
- ✓ Batch processing tools
- ✓ Data migration scripts
- ✓ One-time utility scripts
- ✓ Scripts documentation

**Run from:** Root directory (`/`)

**Example:**
```bash
# From root directory
npx tsx scripts/batch-transform-exams.ts examenes/ --year 2025
```

---

### `/examenes/` - Source Data
**Purpose:** Raw/source exam JSON files before transformation.

**What belongs here:**
- ✓ Original exam JSON exports
- ✓ Raw data files
- ✓ Unprocessed exam files

**Note:** These are INPUT files. The scripts read from here and output to `code/src/data/exams/`.

---

### `/code/src/data/exams/` - Processed Exams
**Purpose:** Transformed exam JSON files in TestNauti format, ready to be imported by the app.

**What belongs here:**
- ✓ Processed exam files (e.g., `2025-per-exam69.json`)
- ✓ Files matching the `Exam` TypeScript interface
- ✓ Files referenced in `loadExams.ts`

**Generated by:** Scripts in `/scripts/`

**Consumed by:** Application code (`src/lib/loadExams.ts`)

---

## Separation of Concerns

### Why this structure?

**Clean Separation:**
- `/code/` = "What the app needs to run"
- `/scripts/` = "Tools to prepare data"
- `/examenes/` = "Raw source data"

**Benefits:**
1. **Clear Purpose:** Each directory has a single, clear responsibility
2. **Portability:** `/code/` can be deployed without scripts or source data
3. **Maintainability:** Scripts and app code don't mix
4. **Scalability:** Easy to add more scripts or data sources

**Deployment:**
- Only `/code/` gets deployed to production
- `/scripts/` and `/examenes/` remain on development machines

## Workflow Example

**Adding 60 new exams:**

```bash
# 1. Add source files
cp ~/downloads/exam-*.json examenes/

# 2. Transform (from root)
npx tsx scripts/batch-transform-exams.ts examenes/ --year 2025

# 3. Update imports (from root)
npx tsx scripts/update-exam-registry.ts

# 4. Build and test (from code/)
cd code/
npm run build
npm run dev
```

**Result:**
- Source files: `examenes/exam-*.json` (untouched)
- Processed files: `code/src/data/exams/2025-per-exam*.json` (generated)
- Imports: `code/src/lib/loadExams.ts` (auto-updated)

## Key Files Reference

### Application Entry Points
- `code/src/app/page.tsx` - Landing page
- `code/src/app/app/exams/page.tsx` - Exam catalog
- `code/src/lib/loadExams.ts` - Exam loading system

### Data Flow
```
examenes/*.json
    ↓ (scripts/batch-transform-exams.ts)
code/src/data/exams/*.json
    ↓ (scripts/update-exam-registry.ts)
code/src/lib/loadExams.ts
    ↓ (import statements)
Application runtime
```

### Configuration Files
- `code/package.json` - App dependencies
- `code/tsconfig.json` - TypeScript config
- `code/next.config.js` - Next.js config
- `code/tailwind.config.ts` - Tailwind config
- `code/prisma/schema.prisma` - Database schema

## Best Practices

### DO ✓
- Keep scripts in `/scripts/`
- Keep source data in `/examenes/`
- Run scripts from root directory
- Run app commands from `/code/` directory
- Commit processed exams to git (in `code/src/data/exams/`)

### DON'T ✗
- Don't put scripts in `/code/`
- Don't put source data in `/code/`
- Don't manually edit `loadExams.ts` imports (use the script)
- Don't run npm commands from root (go to `/code/` first)
- Don't commit raw source files to git (optional, depends on strategy)

---

## Future Additions

If you add more tooling, follow the same pattern:

**Data processing scripts** → `/scripts/`
- Image optimization
- Database seeders
- CSV importers
- Migration tools

**Source data** → `/examenes/` or create new directories
- `/examenes/` - Exam data
- `/imagenes/` - Image assets (if needed)
- `/datos/` - Other data sources (if needed)

**Application code** → `/code/src/`
- Always keeps app code separate from tooling
